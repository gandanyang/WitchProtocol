# 开发约束与架构入口

> 所有 AI 改代码前必读。这里定义：分层架构怎么长、加系统时该往哪放、以及「新增系统检查清单」。

## 一、架构总览（分层）

```
┌─────────────────────────────────────────────┐
│ 场景层 scenes/（Main 主场景 / Boot 开发自检）                    │
│   ├─ 场景脚本 scripts/scenes/                │
│   └─ 只做装配与输入转发，不写业务逻辑        │
├─────────────────────────────────────────────┤
│ 玩法层 scripts/                              │
│   ├─ player/   玩家控制器                    │
│   ├─ bullet/   弹幕系统（池/Pattern/发射器） │
│   └─ ui/       HUD 等                        │
├─────────────────────────────────────────────┤
│ 全局单例（autoload，/root 下唯一实例）       │
│   ├─ GameManager  运行态/视口/场景路由       │
│   ├─ EventBus     跨系统事件解耦             │
│   ├─ SaveSystem   唯一持久状态入口           │
│   └─ DevTestHub   测试探针/种子（DEV）       │
├─────────────────────────────────────────────┤
│ 数据层 data/（.tres 资源配置）               │
└─────────────────────────────────────────────┘
```

依赖方向：**场景层 → 玩法层 → 全局单例 → 数据层**。不允许反向依赖（如 autoload 依赖场景层）。

## 二、各层职责与纪律

### 全局单例（autoload）

| 单例 | 职责 | 纪律 |
|---|---|---|
| `GameManager` | 游戏阶段、PlayfieldSize、场景路由 | 通过 `GameManager.I` 访问；不存业务存档 |
| `EventBus` | 低频跨系统事件 / 一次性事件 | hotpath 不走总线（见红线四） |
| `SaveSystem` | 唯一持久状态入口 | 存档红线见 `docs/dev/SaveSystem.md` |
| `DevTestHub` | 测试探针/种子注册与运行 | 发布构建隐藏，见 `AI_GUARDRAIL.md` |

新增单例需过「新增系统检查清单」，并在 `project.godot` 的 `[autoload]` 登记。

### 弹幕系统（scripts/bullet/）

| 文件 | 职责 |
|---|---|
| `Bullet.cs` | 单发子弹（运动 + 生命周期） |
| `BulletPool.cs` | 对象池（预热/复用/出屏回收/扩容） |
| `BulletPatterns.cs` | Pattern 纯函数（aimed/spread/ring/spiral） |
| `BulletEmitter.cs` | 发射器（把 Pattern 向量喂给池） |
| `PatternSpec.cs` | Pattern 数据规格（数据驱动） |

### 数据层（data/）

- `.tres` 资源 = 静态配置（角色数值、弹幕参数等）。
- 运行时用 `GD.Load<T>` 读取，**禁止硬编码魔法数值**。

## 三、新增系统检查清单（加任何系统前先过）

1. 这个系统是**完成现有闭环**需要的，还是「看起来酷」的新功能？
2. 它属于哪一层？放对目录了吗？（场景层 / 玩法层 / 单例 / 数据层）
3. 它会不会破坏已验证的 **5 个探针**？
4. 它有明确的验证方式吗？（探针 / 种子 / 手动测试脚本）
5. 涉及持久化吗？涉及 → 必须过 `docs/dev/SaveSystem.md` 红线。
6. 依赖本机路径 / 外部服务吗？涉及 → 禁止写死入库。

> 任何一项答不上来，先回 `AGENTS.md` 重新读，或找制作人对齐，不要直接动手。

## 四、新增场景规范

- 场景文件放 `scenes/`，脚本放 `scripts/`（与场景同名的 `.cs` 放 `scripts/scenes/` 或对应子目录）。
- 场景脚本只做**装配 + 输入转发**，业务逻辑下沉到玩法层/单例。
- 主场景 `run/main_scene` 指向 `scenes/Main.tscn`（**正式游戏入口**）。
- **Boot.tscn = 开发 / 自检场景（Dev / Diagnostic Scene）**：
  - 用途：开发自检、基础设施诊断、孤立系统测试；
  - **禁止**：作为正式游戏入口、承载正式玩法逻辑；
  - 改主场景需确认 autoload 初始化链路不受影响。
